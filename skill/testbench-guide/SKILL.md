# 自检式 testbench：写完 HDL 怎么确认它"算得对"

> **归属**：`workflow/` 工作流 —— **换任何 HDL 工程都能用**。
> 配套提示词 **W11**。

---

## Purpose

**目的**：在**上板之前、综合之前**，用仿真回答一个综合结果和肉眼都答不出来的问题 ——
**这个模块算出来的数，到底对不对？**

**预期产出**：

| 产出 | 内容 |
|---|---|
| 自检式 testbench | 一个文件，跑完自己打印 `RESULT: PASS` / `RESULT: FAIL` |
| 仿真日志 | `xvlog` → `xelab` → `xsim` 三步的输出 |
| 一句话结论 | `N 个用例，M 个失败`（M 必须为 0） |

**前置条件**：

- DUT 能通过 `xvlog` + `xelab`（**仿真不需要综合、不需要位流**）
- 能写出期望值（哪怕要手算；见 Workflow Step 2）

---

## When to Use

- 刚写完一级 HDL，**编译通过**了，但不确定算出来的数对不对
- 这一级的错误是**数值型**的（阈值判断、位宽截断、边界拍），**上板肉眼看不出来**
- 手里暂时没有位流、也不想跑综合
- 改动了既有模块的内部逻辑，要确认没改坏行为

## When NOT to Use

- **纯连线 / 纯例化的模块** —— 没什么可测的
- DUT 连 `xvlog` 都过不了 —— 先修语法，别急着写测试
- 想验证**时序能不能收敛** —— 那是综合/实现报告的事，仿真证明不了
- 想验证**上板后的真实行为** —— 那要用 ILA/VIO 抓真实波形，仿真里的激励是人造的

---

## DO's

- **先写"这一级应该算出什么"，再写激励** —— 判据先行
- **期望值手算或查标准**，不要用 DUT 自己的公式反推（那是循环论证）
- **边界值优先**：`0` / 最大值 / **恰好等于阈值的值** / **恰好进位的值**
- 每个用例都 `$display` 打出输入和实际输出，失败时能看到差在哪
- 比对一律用 `!==`（连 `x`/`z` 一起抓），不要用 `!=`
- 单拍脉冲用**标志位捕获**，别在时间点上查
- 跑完统计 `errors`，给出 `PASS` / `FAIL` 的**单一结论**

## DON'Ts

- **不要打波形让人自己看** —— 那不叫验证，叫把问题推给人
- **不要用 `$display` 打一堆数就完事** —— 必须自己比对、自己判定
- **不要一看 FAIL 就改 DUT** —— 先分辨是 DUT 错还是测试错（见 Workflow Step 6）
- **不要在 `negedge` 驱动后让任务恰好停在 `negedge`** —— 会撞上事件队列，出偶发难复现的错
- **不要照抄 RTL 的算式当期望值** —— 公式错了两边一起错，测试永远 PASS

---

## ★ 第一原则：**编译过 ≠ 算得对**

| 手段 | 能证明什么 | 证明不了什么 |
|---|---|---|
| `xvlog` / `xelab` | 语法合法、位宽自洽、模块连接对 | **算出来的数对不对** |
| 综合 | 能变成电路、资源占用 | **算出来的数对不对** |
| **testbench 仿真** | **行为正确性** | 时序能不能收敛 |

**⇒ 一个真实的例子**：本项目一级模块的参数锁存有个错 —— 帧首那个像素用的是**上一帧**的参数。
它只占一帧 70 万个像素里的**一个**，上板肉眼**绝对看不出来**，但它会让"刚关掉使能"那一帧的
计数和标志位整个带偏。**这个 bug 是被 testbench 抓出来的，不是想出来的。**

## Workflow

### Step 1：搭骨架（自检式，不是波形式）

核心是"自检" —— 自己比对、自己报错、给出 PASS/FAIL。

```verilog
`timescale 1ns / 1ps

module tb_xxx;
    // ---- 输入 ----
    reg  clk = 0, rst_n = 0;
    reg  in_valid = 0;
    reg  [7:0] in_data = 0;

    // ---- 输出 ----
    wire out_valid;
    wire [7:0] out_data;

    // ---- 统计（★ 必须有）----
    integer errors = 0;
    integer tests  = 0;

    xxx_stage dut ( .clk(clk), .rst_n(rst_n), .in_valid(in_valid), .in_data(in_data),
                    .out_valid(out_valid), .out_data(out_data) );

    always #5 clk = ~clk;                 // 100 MHz

    // ★ 比对任务：给输入、等稳定、比对、计数
    task check(input [7:0] d, input [7:0] exp);
        begin
            @(negedge clk);               // 在时钟低电平改输入，避免竞争
            in_data  = d;
            in_valid = 1'b1;
            #1;                           // 纯组合逻辑：等 1ns 稳定
            tests = tests + 1;
            if (out_data !== exp) begin   // ★ 用 !== 而不是 !=，连 x/z 一起抓
                errors = errors + 1;
                $display("  FAIL  in=%0d  out=%0d  期望=%0d", d, out_data, exp);
            end else begin
                $display("  ok    in=%0d  out=%0d", d, out_data);
            end
            #4;
        end
    endtask

    initial begin
        rst_n = 0; #20; rst_n = 1; #10;   // 复位
        // ... 一堆 check(...) ...
        $display("==== %0d 个用例，%0d 个失败 ====", tests, errors);
        if (errors == 0) $display("RESULT: PASS"); else $display("RESULT: FAIL");
        $finish;
    end
endmodule
```

### Step 2：定期望值 —— 手算或写"黄金参考函数"

**期望值不能用 DUT 的公式算**。用同一个算式推出来的是**循环论证**：公式错了两边一起错，测试永远 PASS。

两种正确做法：

1. **手算**：写测试时在注释里把推导过程写一遍（本项目灰度测试就是这么做的，8 个值全部手推）
2. **写一个"黄金参考函数"**：换个算法重算同一个式子。例如 RTL 用的是"逐级加宽"的写法，
   参考函数就用普通整数算 —— 专门抓**位宽写错、取位写错**

### Step 3：选边界值，不要只测"正常情况"

**优先测**：`0` / 最大值 / **刚好相等的那个值** / **刚好进位的那个值** / 符号边界。

本项目的实例：

```
算式里有 S + (S>>3)，其中 >>3 是截断的
⇒ 特意构造 S = 8（刚好让 S>>3 从 0 变成 1）来测进位边界
```

> 例：比较器用 `>` 还是 `>=`，只有**喂一个"恰好等于阈值"的值**才测得出来。

### Step 4：跑三步（不需要综合）

```
xvlog <dut.v> <tb.v>          # 编译
xelab <tb名> -s <快照名>       # 展开，出仿真快照
xsim  <快照名> -R              # 跑
```

### Step 5：判 PASS / FAIL

**判据**：末尾必须打印 `RESULT: PASS`，且 `0 个失败`。
只要有一个 FAIL，就回到 Step 6 分辨责任人，**不要直接改 DUT**。

### Step 6：失败时先分辨是 DUT 错还是测试错

**别一看 FAIL 就改 DUT。** 本项目第一次跑报 4 个 FAIL，其中**只有 1 个是真的 DUT bug**，
另外 3 个都是测试自己的错。改错对象会把真 bug 掩盖掉。

| 失败模式 | 更像谁错 |
|---|---|
| **整块行为错**（比如"使能关了还命中"） | DUT |
| **差 1**（计数多一个、晚一拍） | **测试**（多送了一拍 / 采样时机不对） |
| **只有最后一个数据错** | **测试**（末尾没撤销输入） |
| 所有用例错同一个方向 | DUT 的公式或位宽 |

## 五条关键技巧（都是踩出来的）

### 1. 期望值必须**手算**，不能用 DUT 的公式算

见 Workflow Step 2。

### 2. 边界值优先选

见 Workflow Step 3。

### 3. **单拍脉冲**要用标志捕获，别直接在时间点上查

```verilog
reg pulse_seen = 0;
always @(posedge clk) if (done) pulse_seen <= 1'b1;   // ★ 抓住它
// 后面查 pulse_seen，就不会因为查的时机刚好错过而误报
```

**注意**：如果脉冲本身是**延后一拍**出来的（比如"帧尾延后一拍"的 done），
那标志位要**再等一个时钟沿**才采得到 —— **在采样完成前就检查，会误报"没见到脉冲"**。

### 4. ★ 送完最后一个数据，要**先撤销输入再等时钟沿**

```verilog
    send_last_item(...);
    #1;                        // 等锁存结果落地
    @(negedge clk);            // ★ 先到时钟低电平
    in_valid = 1'b0;           // ★ 撤销输入
    in_eof   = 1'b0;
    // 然后再等时钟沿、再检查
```

**不这么做的后果**：最后一个数据（连同它的 `eof`）会在**下一个时钟沿被再算一次** ——
计数会多 1，而如果它刚好带 `eof`，**整个结果会被重复锁存一次**。

> 本项目第一次跑就栽在这：命中数 4 变成了 5。

### 5. ★ 模块带寄存器时：延迟要**查两遍**，才能证明是"正好 N 拍"

技巧 4 的写法（在 `negedge` 改输入、任务结尾刚好停在沿上）只适合**纯组合**模块。
一旦这一级插了流水寄存器，就要换成"固定相位 + 查两遍"：

```verilog
task step(input [7:0] d);
    begin
        // 驱动点固定在"时钟沿之后 1ns" —— 离下一个沿还有 9ns，绝不抢沿
        in_data  = d;
        in_valid = 1'b1;

        // 检查①（沿还没到）：输出**必须还是上一拍的值** ⇒ 证明延迟不是 0
        if (out_data !== ex_data) begin errors = errors + 1; $display("延迟是 0 拍？"); end

        @(posedge clk); #1;            // 过沿，寄存器已更新

        // 检查②（沿之后）：输出**必须正好是本拍输入** ⇒ 证明是 1 拍，不是 2 拍
        if (out_data !== gold(d)) begin errors = errors + 1; $display("延迟不是 1 拍"); end

        ex_data = gold(d);             // 供下一拍做检查①
    end
endtask
```

**三个要点**：

1. **驱动点固定在"沿之后 1ns"**。如果在 `negedge` 驱动、而任务结尾又刚好落在 `negedge` 上，
   下一个 `@(negedge clk)` 会等到**再下一个** `negedge`（白白插进一拍）；
   更糟的是任务结尾和时钟翻转发生在**同一时刻**，谁先谁后要看事件队列，会出**偶发、难复现**的错。
2. **任务必须每次停在同一个相位**（比如永远停在"沿之后 1ns"），下一次调用才能直接驱动输入，不用重新对齐。
3. **期望值用独立写的"黄金参考函数"**。别照抄 RTL 的写法 —— 抄了就变成循环论证。
   参考函数换个算法重算同一个式子（比如用普通整数算，而不是照抄逐级加宽的写法），
   专门用来抓"**位宽写错、取位写错**"。

**验收判据**：跑完 `错误数 = 0`，才算这一级的**延迟和数值同时**正确。

## ★ 集成测试的「延迟账」：分清输出拍与"它描述的那个位置"（2026-10-11 实测）

多级流水做集成验证时，**"逐像素比对报上千条错、而各级单元 TB 全绿"**几乎一定是**模型口径**错了，不是 RTL 错。
三条铁律，全部由本项目实测换来。

### ① 期望值按"描述位置"算，LAT 只用来决定"第几拍去查"

输出的**第 j 拍**装的是**输入第 j−LAT 拍那个像素的判定结果** ⇒ 期望值查 `mask[输入拍自己的坐标]`（**off = 0**）。
把"坐标左移"和"LAT 变小"混着算（两个自由度同时动）是这类 TB 最常见的错。

**LAT 必须实测，不能按寄存器数推** —— 一级内部的行缓存就有几十拍，是延迟的大头
（本项目：取或链 338、形态学旁路 342、闭运算 470）。标定法：全图只放**一个亮点**，量它从输入第几拍走到输出第几拍：

```verilog
// 单点经过"开运算"是恒等的（膨胀成 3×3、腐蚀回来还是它自己）⇒ 闭运算链也能用单点标定
LAT = (命中输出的那一拍) - (row*W + col);
```

### ② 期望写进"它到期的那一拍"的槽位；环形缓冲深度必须 > 最大延迟

```verilog
sn = (cyc + LAT) % RING;        // ★ 写入时就按"到期拍"落位
so = cyc % RING;                // 到这一拍直接读自己的槽位
if (dut.out_valid && h_val[so]) 比对(hit, h_exp[so]);
```

- ★ **坑**：延迟升到 343 而 `RING` 还是 256 ⇒ 槽位**早被覆盖**，读到的是 87 拍前的期望 ⇒ **1107 条假失败**（看着像 RTL 错）。
- 这么写还顺带解决"同一条链两种配置下延迟不同"（470 / 342）：写入时按当时的模式算到期拍，**不会串槽**。
- 比对**使能直接用 DUT 自己的 `valid`**（`t_valid` / `mor_valid`）：有效区的形状是模块内部几何（含行列边界），自己推迟早差几拍。

### ③ 计数类判据要按"描述位置"划区，不能按"输出拍自己的行列"

DUT 的帧内计数器数的是**有效输出拍**，而这些拍描述的画面位置整体**前移了 LAT** ⇒ `计数区 = 有效输出拍的区间 − LAT`。
本项目实测：形态学级有效输出 = **18 行 × 58 拍**，帧内光栅上第 k 行是 `[408+64k, 465+64k]`；
按"输出拍自己的行列"（行 6..23 / 列 6..63）划区 ⇒ **每个用例都差 5~7 行**（实测模型 34 而 DUT 26），全成了假失败。

**还必须知道**：行缓存是**连续流上的延迟线**（不按帧清零）⇒ 帧首两拍的窗口看到的是**上一帧最后两行**。
图案若画到帧底，帧首会**凭空多出命中**（实测用例 5 多 6 个）。
⇒ 图案收在描述区内部（实测收在 8..16 行后，边界杂散 = 0），把"帧边界行为"**单独记录、单独看待**，
**不要**为了让测试变绿去放松判据。

### 仿真工具坑：`xvlog` 秒级没输出 = 卡死了

现象：`xvlog` CPU 满载、日志 0 字节、几分钟不返回（`work` 库状态坏了）。**别等**，换个干净库名即可：

```powershell
xvlog -work lint <所有源文件>     # 换库名
xelab lint.<top> -s <snap>        # 顶层要带库名前缀
xsim <snap> -R
```

（本项目 `_lint\xsim.dir\work` 就是这么坏掉的，改名留档后一直用 `-work lint`。）

## 来源（从哪些失败或观察中总结得出）

**触发**：需求方说"**以后你都需要自己编译，起码要编译过才能说对阿**"，
随后又澄清"**就是要到可以仿真那步**" ⇒ 说明他要的验收标准**本来就是"能仿真"**，
而"编译过"只是最低门槛。

**踩的坑（三条，全部来自本项目）**：
1. **DUT 真 bug**：参数在帧首时钟沿锁存，而帧首像素在同一拍的组合通路上判定 ⇒ **帧首像素用上一帧的参数**
2. **测试错①**：送完最后一个像素后又等了一个时钟沿 ⇒ **末像素被算两次**（命中数 4→5）
3. **测试错②**：`done` 是延后一拍的脉冲，标志位还没采样到就去检查 ⇒ **误报"没见到脉冲"**

**⇒ 最有用的一条结论**：**"编译过"和"算得对"是两回事，而边界拍（帧首/帧尾）是最容易错的地方。**
