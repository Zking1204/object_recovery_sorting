# 自检门禁（改动工具脚本的标准写法）

> **归属**：`workflow/` 工作流 —— 换任何"用脚本改工程/改文件"的场合都能用。
> 配合提示词 **W5**。

---

## Purpose

**目的**：**让"失败"变成无副作用的失败。**

**预期产出**：

| 产出 | 说明 |
|---|---|
| 一个脚本 | 改完 → 自检 → **全过才保存**；不过就退出，盘上文件原样 |
| 一份摘要 | 结尾打印"改了什么、还剩什么、关键值"，事后 grep 就能核对 |
| 一条删除纪律 | 删/搬"内容已搬走"的文件前，**先逐条核对覆盖率** |

**前置条件**：你能写出"改动成功的判据"（写不出判据就没法做门禁）。

---

## When to Use

- 写任何**会修改工程 / 会修改文件**的脚本时
- 改动涉及**结构性操作**（增删 cell、改连接、扩互联端口、分配地址）
- **要删除或迁移一个"内容已转移到别处"的文件**（见文末特例）

## When NOT to Use

- **需要"边改边试"的探索性改动** —— 那种应该先在一个**副本**上做
- 只读脚本 / 只打印不写盘的脚本 —— 没有副作用就没有门禁的必要

> ⚠️ 门禁只能保证"**结构自洽**"，**不保证语义正确** ——
> 它不会告诉你"这个连接在逻辑上对不对"，那要靠 `../verification-methods/SKILL.md`。

---

## DO's

- **先备份**（备份 2~3 秒，返工几十分钟）
- **每一步都 `catch` 住**，单步失败立即停，不带坏状态继续
- **自检项要覆盖双向**：增/删计数、连接是否同网、时钟复位是否同网、地址是否分配
- **自检比对"引脚列表"而不是"网络名"**（网名用下划线、引脚名用斜杠，容易误判）
- **保存之前先跑一次结构预检**（Vivado 里是 `generate_target`），把结构错挡在长编译之前
- **结尾打印可核对摘要**，事后 grep 日志就能判据
- **脚本纯 ASCII**（含中文注释的脚本喂给某些工具会按 cp936 解析成乱码）

## DON'Ts

- **不要"改到一半保存"** —— 保存动作必须在所有自检之后
- **不要只 `catch` 不判定** —— `catch` 只是不让它崩，还要检查返回值和状态
- **不要在删除/迁移文件时，仅凭"我记得已经搬完了"就动手** —— 见文末特例

## Workflow

### Step 1：先备份，并把备份路径打印出来

### Step 2：自检「改动前」状态
（比如 cell 总数、关键网络是否存在）—— 状态不对就直接退出，说明这不是你以为的那个工程版本。

### Step 3：做改动（每一步都 `catch`）

### Step 4：自检「改动后」状态
逐项打印 + 判定，用一个 `ok` 变量累积。

### Step 5：编译/构建之前先跑结构预检
（1 分钟就能把结构错误挡在 6~25 分钟的构建之前。）

### Step 6：**只有全过才保存**；否则退出并保持盘上原样

## 模板（Tcl 版，Vivado 场景）

```tcl
proc abort_ {msg} {
    puts "ABORT: $msg"
    catch {close_bd_design [current_bd_design]}
    catch {close_project}
    exit 1
}

file copy -force $bdfile $bdbak          ;# ① 先备份
puts "BD_BACKED_UP=$bdbak"

open_project $proj
open_bd_design [get_files design_1.bd]

# ② 自检「改动前」状态
set n_before [llength [get_bd_cells]]
if {$n_before != 16} { abort_ "unexpected cell count $n_before" }

# ③ 做改动（每一步都 catch 住，失败即 abort）
if {[catch {create_bd_cell -type module -reference my_mod my_mod_0} e]} {
    abort_ "create_bd_cell failed: $e"
}

# ④ 自检「改动后」状态：逐项打印 + 判定
set ok 1
if {[llength [get_bd_cells -quiet old_mod]] != 0} { puts "CHECK FAIL: old_mod still here"; set ok 0 }
set n1 [get_bd_intf_nets -quiet -of_objects [get_bd_intf_pins src/M00_AXIS]]
set n2 [get_bd_intf_nets -quiet -of_objects [get_bd_intf_pins my_mod_0/s_axis]]
if {$n1 eq "" || $n1 ne $n2} { puts "CHECK FAIL: not on same net"; set ok 0 }

# ⑤ 编译前预验证（把结构错误挡在长编译之前）
if {$ok} {
    if {[catch {validate_bd_design} verr]} { puts "VALIDATE_ERROR: $verr"; set ok 0 } else { puts "VALIDATE_OK" }
}

# ⑥ 只有全过才保存
if {$ok} {
    save_bd_design
    puts "BD_SAVED_OK"
} else {
    puts "BD_NOT_SAVED -- 自检没过，盘上文件保持原样"
    catch {close_bd_design [current_bd_design]}
    catch {close_project}
    exit 1
}
```

> **Python / PowerShell 版同理**：核心是"**所有写盘动作集中在最后，且由 `ok` 变量把关**"。
> 别用"改一次写一次"的写法。

## 六条要点

| # | 要点 | 为什么 |
|---|---|---|
| 1 | **先备份** | 备份 2~3 秒，返工几十分钟 |
| 2 | **每步 `catch`** | 单步失败要立即停，不要带坏状态继续 |
| 3 | **自检要比"引脚列表"而非"网络名"** | 网名用下划线、引脚名用斜杠，容易误判 |
| 4 | **自检项要覆盖双向**：增/删计数、连接是否同网、时钟复位是否同网、地址是否分配 | 少一项就可能漏掉一类错 |
| 5 | **编译前先跑一次 `generate_target`（或等价的结构预检）** | 1 分钟就能把结构错误挡在 6~25 分钟编译之前 |
| 6 | **结尾打印可核对摘要** | 事后 grep 日志就能判据，不必重跑 |

## 已验证效果

**本项目用这套做完"拆帧差器 + 插自研模块 + 扩 AXI 互联 M 口"三个动作，一次成功**：
- `validate_bd_design` 干净
- `generate_target all` 通过
- 编译 0 Errors / 0 Critical Warnings

**并且它救过一次场**：第一次跑时脚本因 AI 自己的 Tcl 语法错（`$var(0)` 被当成数组下标）**中途崩溃**，
**正因为门禁在保存之前，盘上的工程文件毫发无伤**，修完 bug 重跑即可。

## ★ 特例：删除或迁移"源文件"之前，先核对覆盖率（G12）

**触发场景**：你要删掉/搬走一个文件，理由是"**它的内容已经全部转移到别处了**"。

**⚠️ 危险在哪**：这个理由**常常是大模型自己给出的**（"我已经把内容全部拆进新目录了"），需求方只是采信。
而一旦判断有误，**内容就永久消失了** —— 尤其在**工作区没有 git** 的情况下，**没有 undo**。

**做法（三步，缺一不可）**：

1. **先把源文件里的条目编号全部列出来**（如 `grep '^## ' 源文件`）—— 这是"应该被搬运的总数"。
2. **逐条去目标文件里找对应**，产出一张两列表：`条目 → 落在哪个文件的哪一节`。
3. **凡是对不上的，先补完再删**；补不了的就**别删源文件**。

**真实案例（本项目）**：需求方同意"删掉原料仓 `SKILL_SOURCE.md`，内容已全部拆进三块目录"。
逐条核对后发现 **P4 / P5 / P8 / P9 / G2 / G3 / G4 共 7 条根本没搬**（另有 1 条只搬了一半）——
如果直接删，**7 条经验连同原始要求一起没了**。

**顺带教训**：搬运还会产生**悬空引用** —— 本项目一处写着"见某个已被改名的旧条目"，
而那个文件里**根本没有这条内容**（作者记错了编号）。
**⇒ 所以第 1 步的清单里也要包含"所有指向源文件的交叉引用"，逐个改指向。**

**与"门禁"的关系**：门禁管的是"**改**"，这一条管的是"**删**"。
前者保证出错时盘上文件不变，后者保证**根本不会有东西被删错**。

## 来源（从哪些失败或观察中总结得出）

1. 本项目一次改动脚本中途崩溃，**门禁保住了工程文件**。
2. 另一次改动**扩了 AXI 互联的口却没连时钟、没分地址** ⇒ 生成 HDL 直接失败、整个工程没法编译
   ⇒ 从此把"时钟/复位/地址"三件套写进自检清单。
3. 一次"内容已搬走"的删除请求，逐条核对后发现**7 条压根没搬**（第 12 条经验 G12 的来源）。
