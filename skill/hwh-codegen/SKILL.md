# 从 `.hwh` 自动生成主机侧代码与自检骨架

> **归属**：`pynq/` 通用 PYNQ 技能 —— **完全独立于本队题目** ⇒ 官方点名的"通用 PYNQ Skill"。
> **⚠️ 状态：【规划中 · 尚未实现】。** 本文件写的是**完整方案**，不是已验证成果 —— 请按此判读，不要当成品引用。

---

## Purpose

**目的**：把"**每次改完 BD 就手工 grep 一遍 `.hwh`**"这件事，变成**跑一次脚本**。

**预期产出**：

| 产出 | 说明 |
|---|---|
| 寄存器访问类 | 每个 IP 一个 `.py`，取代裸 `MMIO(base, size)` 到处写 |
| 地址常量表 | `ADDR = {"axi_vdma_0": 0x43000000, ...}` |
| 读回自检骨架 | 加载 overlay 后逐个 IP 验证"通路通了" |
| IP 清单 | 接手陌生工程的第一份材料 |

**前置条件**：有 `.hwh`（不用 PYNQ / 没有 `.hwh` 的场合不适用）。

---

## When to Use

- 刚拿到一个**陌生的 overlay**，想知道"这里面到底有什么 IP、地址在哪"
- 每次改完 BD 都要**手工**从 `.hwh` 里 grep 地址、grep 端口名
- 想给每个 IP 写一个 Python 寄存器访问类（反复手写同样的模板）
- 想要一个"**上板后逐个 IP 跑一遍读回自检**"的骨架

## When NOT to Use

- 不用 PYNQ / 没有 `.hwh` 的工程（裸机、PetaLinux 纯 C 场合 `.hwh` 不参与）
- 只需要查一两个地址的临时场合 —— 直接 grep 更快

---

## DO's

- 先看清 `.hwh` 里已经有什么（见下表），**别重复造轮子**
- **把"频率不可信"这条写进生成器**：`CLKFREQUENCY` 只导出、不判定
- 生成器要**容忍 `.hwh` 被外部脚本补丁过**（本项目每次重编后都会改 FCLK0 分频参数）
- 生成的自检骨架**在板上真跑一遍**，把结果打成表留档

## DON'Ts

- ⚠️ **不要把 `.hwh` 里的 `CLKFREQUENCY` 当频率证据** —— 它含工具推断
- **不要假设 `.hwh` 等于工具原始输出** —— 它可能被补丁过

---

## 为什么这件事"容易做"

`.hwh` 就是**文本 XML**，里面已经把你要的东西全写好了：

| `.hwh` 里的东西 | 能直接生成什么 |
|---|---|
| 每个 IP 的 `MODULE` / `VLNV` / `PARAMETER` | IP 清单 + 型号 + 关键参数（如 VDMA 的 `C_NUM_FSTORES`） |
| `C_BASEADDR` / `C_HIGHADDR` | **地址常量表** |
| `MEMRANGE` | 地址空间划分 |
| 端口名与位宽 | 总线宽度、方向 |

**⇒ 结论：这是一次性的解析脚本 + 模板渲染，不需要任何硬件知识。**

---

## 计划生成的四样东西

| # | 产物 | 用途 |
|---|---|---|
| ① | 每个 IP 一个 **Python 寄存器访问类** | 取代裸 `MMIO(base, size)` 到处写 |
| ② | **地址常量表**（`ADDR = {"axi_vdma_0": 0x43000000, ...}`） | 杜绝手抄地址写错 |
| ③ | **读回自检骨架** | 加载 overlay 后逐个 IP 验证"通路通了" |
| ④ | **"这个 overlay 里有什么"清单** | 接手陌生工程的第一份材料 |

## Workflow（建议的实现路线）

```
① 解析  design_1_wrapper.hwh  →  用 xml.etree 遍历
② 抽取  {实例名: (VLNV, BASEADDR, HIGHADDR, 关键参数, 端口)}
③ 渲染  Jinja2 或 f-string 模板  →  生成 .py
④ 自检  生成的骨架在板上跑一遍，把结果打成表
```

**⚠️ 两个已知的坑（本工作区实测，务必绕过）**：

1. **`.hwh` 里的 `CLKFREQUENCY` 含工具推断**（顺着参考时钟往下传）⇒ **不能当频率证据**。
   频率必须落到"谁驱动它"的网表连接上（见 `../verification-methods/SKILL.md`）。
2. **`.hwh` 可能被外部脚本补丁过**（本项目每次重编后都要改 FCLK0 分频参数）。
   ⇒ 生成脚本**不要假设 `.hwh` 等于工具原始输出**。

---

## 工作量估计

**一个下午的量级**（解析 + 模板 + 在板上验证一轮）。

---

## 来源（这个想法是怎么来的）

人工从 `.hwh` 里 grep 地址与连接关系，一次查一两个还可以，改一次 BD 就要从头重查一遍，既慢又容易漏。
这类工作可以完全交给脚本：地址、连接关系、时钟域都已经写在 `.hwh` 里，机械提取即可。
