# 在像素流末端加 OSD 叠加层，以及"加完时序打穿"的正确修法

## 一、这个技能解决什么

两件事，永远是连着出现的：

1. **功能**：画面要出框和字（检测框 + 类别名 + 置信度）。
2. **代价**：加完一综合，**WNS 从正变负**，或者虽然 WNS 看着还行但**关键路径变成了你新加的那块**。

本技能给出：OSD 该放在哪、寄存器怎么打包、**以及一条"绝对不能那么修"的时序修法与一条"应该那么修"的正确修法**。

---

## 二、什么时候用 / 什么时候别用

**用**：
- 图像通路已经跑通，要在画面上**标注**（框、文字、准星、HUD、色条）。
- 加完一层逻辑后时序变差，怀疑是新逻辑的组合链太长。

**别用**：
- 通路还没跑通 —— 先用 `../verification-methods/SKILL.md` 把画面弄对，别叠加装饰。
- 只需要静态图案（Logo、边框）—— 直接叠一个常量层/查 ROM，不需要下面这套打包法。

---

## 三、OSD 层放哪：**最末端，不要插进算法通路中间**

```
摄像机 → 算法链路(多级) → 统计/AXI → VDMA ─┐
                                    ↓        │
                                   OSD ←─────┘   ←★ 放在这里：像素出口的最后一级
                                    ↓
                                  HDMI
```

**三条理由**（每条都是纪律，不是偏好）：

1. **不影响算法**：OSD 放在算法后面，算法看到的一直是干净画面。插在中间 ⇒ 下游算法会去检测你自己画出来的那个框。
2. **不破坏时序对齐**：OSD 让**整幅画面统一晚 N 拍**，相对偏移不变 ⇒ 上板标定过的 `SHIFT_X / SHIFT_Y` **不用重算**。
   ⚠️ 前提是**边带信号（valid / last / user）跟着数据一起打拍**，见第五节。
3. **可以一键旁路**：`CTRL = 0` 时输出与输入**逐像素相等**，出问题不用重编位流。

---

## 四、旁路开关：第一版就要做，别等出事再做

```verilog
// 旁路：CTRL[0]=0 时 pix_out 必须与 pix_in 逐像素相同（不是"看起来像"，是相等）
assign pix_out = en ? mixed : pix_in;
```

**判据**：`CTRL=0` 时把这一级整个当成不存在，下游拿到的数据与不实例化 OSD 时**逐字节一致**。
这条判据可以用 testbench 一行断言钉死（本次 9220 次比较、0 失败）。

---

## 五、AXI 寄存器打包：**基址 + 步长**，别一个字段一个地址

一次要下发几十个数字（每个框 4 个坐标 + 颜色 + 一串字符码），**逐字段一条 AXI 写会把总线打满**，而且 PS 侧代码会长得没法维护。

用**定长记录打包**：

| 偏移 | 内容 |
|---|---|
| `0x44` | `CTRL[1:0]`（bit0 画框 / bit1 画字；0 = 旁路） |
| `0x48` | `N[3:0]`（有效对象数 0–8） |
| `0x4C + 32*k + 0x00` | `{by[31:16], bx[15:0]}` —— 框左上角 |
| `0x4C + 32*k + 0x04` | `{bh[31:16], bw[15:0]}` —— 框宽高 |
| `0x4C + 32*k + 0x08` | `{ty[31:16], tx[15:0]}` —— 文字左上角 |
| `0x4C + 32*k + 0x0C` | `{nchar[6:2], color[1:0]}` —— 字符数（≤16）+ 颜色 |
| `0x4C + 32*k + 0x10..0x1C` | **4 个 32bit 装 16 个字符**，每字节一个 ASCII（小端：第 0 个字符在 bit[7:0]） |

★ **坐标是"高 16 位放 y、低 16 位放 x"**，即 `val = (y << 16) | x`。不要想当然按"用多少位就左移多少位"去拼 —— 本例 `x/y` 各只用到 11 位，但字段位置是**按 16 位对齐**的，写成 `(y << 11) | x` 会全错且不报错。

一个对象 = **32 字节 = 8 个 32bit 寄存器**；PS 侧 `write(0x4C + 32*k + off, val)` 循环即可，加框只加寄存器、**不动 BD、不动端口**。

> ★ **"只加寄存器、不加端口"是刻意设计**：一旦动 BD 端口，就会踩 `module_ref` 端口缓存坑（见 `../vivado-bd-ops/SKILL.md`），而且要重新验证 `.hwh`。加寄存器则 **`.hwh` 逐字节不变 ⇒ 板端不用重传 `.hwh`**。

## 六、组合逻辑怎么切：**比较器 / 优先级 / 字码 一级，字体 ROM / 位选 / 输出 一级**

### 6.1 先看反例（本次真实事故）

第一版把**整条判定链**写成一个 `always @(*)`，然后**只在最后给输出加了一级寄存器**：

```
bx/bw/by/bh 比较器 ×N  →  优先级编码 ×N  →  字符码 mux ×N  →  ┐
                                                          ├→ o_p_reg[9]   ← ★ 全串在一拍里
字体 ROM 读 → 位选 → 颜色选择 ─────────────────────────────┘
```

综合后：**WNS = −3.840024 ns，TNS = −124.948257**。
报告里的路径名把事情说得很清楚：

```
design_1_i/glass_defect_core_0/inst/u_osd/tx_reg[4][3]/C --> .../u_osd/o_p_reg[9]/D
```

**"给最终输出打一拍"不等于"把链路切开"** —— 它只是把终点往后挪了一级，起点到终点之间的组合深度**一点没少**。

### 6.2 正解：在两级之间找**自然分界**，插一整排寄存器

| 级 | 做什么 | 输出 |
|---|---|---|
| **第 1 级** | 所有比较器 + 优先级仲裁 + 字符码 mux | `tx_reg / ty_reg / nchar_reg / color_reg / bbox_*_reg`（打拍） |
| **第 2 级** | 字体 ROM 读 + 像素位选 + 颜色选择 + 与输入像素混合 | `o_p`（打拍） |

- **自然分界在哪？** 找"**下一级必须等上一级算完才能开始**"的那个点：字体 ROM 的地址依赖"当前该显示第几个字符"，而"第几个字符"依赖优先级仲裁结果 ⇒ **必须切开**。
- 切完后：**WNS = +0.240128，TNS = 0.000000**（同一份综合脚本、同一套约束）。
- **LUT 代价**可接受：11,641 → 14,610（27.46% of 53,200），FF 17,704 → 19,643（18.46%）。
- **BRAM 数量不变（14）** —— 见 6.3。

### 6.3 字体 ROM 用 `initial` + 异步读 ⇒ 分布式 RAM，不占 BRAM

```verilog
reg [7:0] font [0:2047];              // 8×8 点阵，2048 字节
initial begin                         // ★ 综合器认这个初始化块
  /* 清空 */
  /* 每个字符 8 行 */
end
assign bits = font[{ch, row}];        // 异步读 ⇒ 推成分布式 LUT RAM（约 256 LUT），不进 BRAM
```

**判据**：`Block RAM Tile` 数字**一个没变**，而 `Slice LUTs` 只涨了几百 ⇒ 说明它确实走了 LUTRAM。
若你写成了同步读（`always @(posedge clk) bits <= font[addr]`），就会占 1 块 BRAM，并且多一拍 —— 而 OSD 这一级**恰好不想多一拍**。

## 七、★ 打拍时最容易漏的：**边带一起打，反压一起冻**

```verilog
// 数据侧多打了一拍，边带必须同步多打一拍，否则 tlast 会提前/滞后一个像素
always @(posedge clk) begin
  if (en) begin
    d_v <= s_v;   // ★ 用 en 门控：反压时整条流水一起冻结
    d_l <= s_l;
    d_u <= s_u;
  end
end

// 反压：只在真正"卸货"那一拍才收下一个像素
wire o_adv = m_axis_tready | ~o_v;
assign s_axis_tready = o_adv;
```

**三条纪律**（与 `../hdl-module-split/SKILL.md` 的打拍三纪律同源）：
1. **数据与 sideband 同拍**：多打了几拍，`valid/last/user` 就补几拍。
2. **`en` 门控而不是裸打拍**：从机没准备好时，寄存器**保持不动**，否则 `tlast` 会被重复/丢失。
3. **`tready` 由"这一拍能不能卸货"决定**，不是由 `tvalid` 决定。

**验证判据**：旁路态（`CTRL=0`）下，把整幅图送进去，输出的 `tvalid/tlast/user` 序列与输入**完全一致，只是整体晚 N 拍**。本次实测 `N=2`。

## 八、标注摆放的两条实用规则（PS 侧）

1. **文字放框上方；上方放不下（`ty < 字高`）就放框下方。** 不要让它跑出画面边界 —— 出界在硬件里**什么都不显示**，很难看出来是"出界"还是"没数据"。
2. **坐标用"画面坐标"，不要用缓冲坐标。** 相机缓冲通常有左边距（本工程 `OFF_PX=160`），缓冲区里的 `x` 与屏幕上的 `x` 差一个常数。**在 PS 侧减掉它，硬件只管画。**

## 九、Workflow 编号步骤

1. 确认算法通路已跑通、画面已对齐（没跑通就别叠）。
2. 定**寄存器打包格式**（第四节），先只做旁路 + 一个框，上板验证"旁路逐像素相等"。
3. 加文字：先只支持**固定 1 个字符**，验证字模正确（用一个已知字母 `A` 的 8 行位图手算期望值）。
4. 加多对象 + 优先级。**同类型多个对象重叠时，最小索引优先**（定死，别让它"看运气"）。
5. **先写自检式 testbench**（`../testbench-guide/SKILL.md`），跑过再综合。
6. 综合 → **立刻看时序**（`../timing-report-reading/SKILL.md`）。WNS 负了先看**关键路径的起终点是不是都在你新加的模块里**。
7. 若负：按 6.2 找分界切流水，**不要**只给输出补寄存器。
8. 回归：重跑 testbench（流水多了一拍，测试要相应改期望延迟）+ 重新上板验旁路与叠加。
