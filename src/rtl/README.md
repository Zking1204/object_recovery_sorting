# PL 侧源码索引

16 个自研 Verilog 文件。每个文件头部都有一段注释块，写明它的**层级、作用、例化者**；
本文件补充**端口组**与**重建者必须知道的行为约束**。

三个模块被 BD 直接引用（`module_ref`，BD 只记模块名、不记文件路径）：
**`glass_defect_core_v2`、`dd_osd_axis`、`servo_pwm`**。这三个名字沿用早期命名，**不要重命名**——
改 `module_ref` 的名字需要删除并重建该 BD 单元，进而触发全量重综合。

---

## 一、定位流水线（整链 14 拍）

| 文件 | 层级 | 作用 | 例化者 | 延迟 |
|---|---|---|---|---|
| `dd_gray.v` | 14 拍链 第 1 级 | 24 位彩色**逐位透传**（名字沿用早期命名，内部不做灰度运算） | `defect_detect` | +1 |
| `dd_pair.v` | 第 2 级 | 相机流与背景流逐 beat 配对，紧反压 1:1 + 帧首锚定 | `defect_detect` | +1 |
| `dd_shadow.v` | 第 3 级 | 由配准后的 A/B 现算 Y/Cb/Cr，抗阴影三判据打分 | `defect_detect` | +5 |
| `dd_win3x3.v` | 第 4 级 | 行缓冲生成 3×3 邻域 | `defect_detect` | +2 |
| `dd_median3.v` | 第 5 级 | 19 比较器网络中值，可旁路 | `defect_detect` | +3 |
| `dd_thresh.v` | 第 6 级 | 固定阈值二值化，极性可配 | `defect_detect` | 0 |
| `dd_morph.v` | 第 7 级 | 3×3 闭运算（先膨胀后腐蚀），可旁路 | `defect_detect` | +2 |
| `dd_sobel.v` | 旁路支路 | Sobel 梯度 L1 幅值 + 二值化，与主链取或进掩膜 | `defect_detect` | +3 |

| 文件 | 端口组 | 作用 | 例化者 |
|---|---|---|---|
| `defect_detect.v` | 纯逻辑（clk / rst_n + 旁听 AXIS） | 定位链顶层：串起 7 级 + Sobel 支路，含帧内统计与影子寄存器 | `glass_defect_core_v2` |
| `glass_defect_core_v2.v` | **AXI4-Lite 从口 + 双 AXIS 输入 + AXIS 输出** | 检测核 BD 顶层（`0x43C2_0000`）：寄存器译码、DISP 档位选择、掩膜输出 | **BD**（`glass_defect_core_0`） |
| `size_detect.v` | 纯逻辑（旁听） | 统计连通区宽/高/面积 | `glass_defect_core_v2` |
| `dd_osd.v` | 纯逻辑 + `wr_en`/地址回读 | 在像素流上叠加矩形框与 ASCII 文字 | `dd_osd_axis`、`glass_defect_core_v2` |

|---|---|---|---|

## 四、重建者必须知道的行为约束

以下不是错误，而是**这批模块的既定行为**——不按它用会得到看起来像 bug 的现象。

| 模块 | 约束 |
|---|---|
| `dd_gray` | 文件名沿用早期命名，**它不做灰度运算**。灰度与色度都在 `dd_shadow` 里现算——配对前灰度化会销毁色度信息，抗阴影就失效了。★ 其单元 TB `sim/tb_dd_gray.v` 是按旧版灰度语义写的、**尚未同步**，复现时跳过该 TB |
| `dd_pair` | `b_sof` 是**电平**不是脉冲，内部按边沿使用。核心不变式：挂起时队首必然是背景帧的首像素。**绝不能用丢数据来做对齐**（每帧丢像素必然漂移） |
| `dd_shadow` | 文件头里"延迟 4 拍"的标注是早期版本；当前实际 **+5 拍**，以本表与 `defect_detect` 的例化处为准。参数经 `0x28 SHADOW_CFG` 下发，写 `[0]=0` 可一键退回纯亮度差 |
| `dd_win3x3` | **行缓冲深度固定 1024**。换更高分辨率（行宽 > 1024）必须同步调整深度，否则会静默回绕。窗口边缘用复制填充 |
| `dd_thresh` | 阈值寄存器 8 位，而 `dd_shadow` 输出的亮度有效档位约 220，所以实际可用阈值范围小于 0~255 |
| `dd_morph` | 含 `initial` 块用于寄存器数组复位；闭运算结构元固定 3×3，不做开运算（开运算会把小目标整体删掉） |
| `dd_sobel` | 与主链**并联**、不串联：串联会让中值先吃掉细目标。Sobel 报的是"边"，取或之后目标会被加宽约 1 像素 |
| `defect_detect` | 三处延迟注释互相不一致（8/10/6 拍），**以本表 14 拍为准**。帧内统计盯的是形态学之后那一路 |
| `glass_defect_core_v2` | 文件头寄存器表里 `0x28` 仍写着旧名 `DEF_STAIN`，**当前实际是 `SHADOW_CFG`**（`[0]` 阴影使能 / `[7:4]` wY / `[11:8]` wC / `[23:16]` τc / `[31:24]` αmin）。`px_eof` 依赖行计数到 719 |
| `size_detect` | 输出当前保持 0，判决链**不依赖**它的结果；它是给后续按尺寸分级预留的位置 |
| `dd_font_rom` | 含 `initial` 块做 ROM 初始化，综合成分布式 ROM，不占 BRAM |
| `dd_osd` / `dd_osd_axis` | 两者各有一套寄存器写入口（`dd_osd_axis` 是给 BD 用的 AXI-Lite 封装）。改寄存器语义时**两处要一起改** |
| `servo_ch` | 同一个 `always` 块里对 `pending` / `pw` / `acc` 有多处非阻塞赋值，**行为依赖书写顺序**，改这段时不要调整语句次序 |
| `servo_pwm` | 文件头写的"周期 20.97 ms"是早期的 `2^21/100MHz` 估算，**实际常量 `PERIOD_CYC = 2e6` 对应 20.00 ms**。脉宽在周期边界才锁存，这是消除"中途改脉宽产生双脉冲 → 舵机抖动"的关键 |
